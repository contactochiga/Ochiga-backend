# Isolated execution preparation — not ready for provider execution

`executor.py` is a durable SQLite budget/intent ledger and adapter orchestration core. `policy.cjs` is the exact-route validator. Both are disabled infrastructure building blocks, **not a completed Paystack run command**. The runtime relay still refuses financial requests, the setup entrypoint refuses processing, and no real-provider adapter is wired to this core. Do not enable financial routes merely because the unit tests pass.

Limits:12 payment initializations,10000 kobo/payment,120000 aggregate;3 full refunds only against a matching verified payment;60 reads,3 replays,60minutes. One payment/refund per scenario. Intent reservation commits before calling an adapter. Interrupted sends remain recorded and stop the run; no blind resend. Restart duplicates return a read-only-reconciliation requirement. Manifest hash, mode, counters and outcomes persist; audit events refuse UPDATE/DELETE. Local operators with filesystem ownership remain trusted; SQLite is not a hostile-user privilege boundary.

Tests: `python3 release/provider-execution/test_executor.py` and `node release/provider-execution/test-policy.cjs`. Tests use mock adapters only, never the injected key or provider API. Real provider proof, callback and refund lifecycle validation remain in existing HardwarePayments/HardwareRecovery services; this ledger cannot replace those services or directly mark Office orders paid.

Remaining integration: wire an adapter through existing Backend hardware services and the route validator; atomically account for every initialization, verification, replay and refund across worker/restart paths; add explicit approval-bound arming and read-only uncertain-outcome reconciliation; persist scenario completion evidence and verify isolated end-to-end with a mock provider. Do not claim automatic idempotent recovery complete: the ledger currently stops safely and preserves uncertain operations for that reconciliation integration.
