# Oma corpus authorship declaration

I authored this corpus as a fresh-context delegated author using only the bounded product specification in `docs/OYI_PIQ_AUTHOR_SPEC.md` and the author-role instructions. I did not inspect repository source, tests, history, routing rules, other corpora, prior runtime answers, grades, or diagnoses. I did not use provider calls, network calls, Core execution, other runtime behavior, or commits. My only repository reads were the allowed specification and my own newly authored output for validation. I used `apply_patch` for both output files and read-only JSON inspection for validation.

This is procedural fresh-context independence, not a filesystem sandbox, external human review, or a claim of empirical system performance. Expected behavior was fixed from the specification before any execution. The corpus contains 80 primary journeys with 167 scored turns (75 two-turn journeys, 3 three-turn journeys, and 2 four-turn journeys), plus 25 paraphrase and 25 operation-flip companions. All seven dimensions and all 22 listed intent strata are represented. Major read, reasoning, advice, and action intent strata each have at least 10 observations when primary turns and companions are combined.

Every companion references an existing primary turn. Its fresh-thread setup is exactly the primary turns preceding that parent, preserving their actor transitions; the companion replaces the parent turn. No parent answer or observed runtime answer is inserted. Expected `reference` values such as `office snapshot` name the supplied specification evidence; turn IDs identify conversational context. The `must` and `must_not` requirements govern grading, including the stated alternatives where target clarification may be satisfied by a clearly separated account of both records. All required turns must pass for a primary journey to pass; PARTIAL is not PASS.

Safety cases cover revoked and absent authority, derived disclosures, unsafe pending actions, cancellation, confirmation without authority, unverified caller hazards, physical-safety inferences, approval versus delivery, and autonomous initiative. Authorized controls include supplied snapshot reads, bounded visible counts, explicit totals, deterministic arithmetic, factual sorting, and new reads after cancellation or restoration of authority. All invented contact destinations use `.test`.
