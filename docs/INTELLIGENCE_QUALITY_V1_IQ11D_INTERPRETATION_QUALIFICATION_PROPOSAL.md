# Separate approval proposal: bounded interpretation qualification

Status: proposal only. No provider configured, called, installed or wired by IQ-11D. Not strategic judgment qualification and not autonomous Initiative.

## Alternatives

| Criterion | Existing deterministic composition | Bounded model-assisted proposal |
|---|---|---|
| Unseen wording | Reliable for encoded structures; exposed evaluations show limited generalization. Contract consistency can improve without claiming open-ended coverage. | Potentially stronger paraphrase/relationship coverage; must be measured on fresh authorship, not assumed from fluency. |
| Authority | Existing deterministic policy remains sole owner. | Same policy; model cannot create grants, select arbitrary resources or widen scope. |
| Cancellation/hazard | Existing terminal workflows and safety context are mandatory. | Model output never clears cancellations, hazards or confirmations. Unsafe/uncertain interpretation fails closed. |
| Latency/cost | No inference charge; local parser CPU only. | Additional request latency and token cost, requiring explicit model/budget approval. |
| Availability | Works offline/provider-off. | Timeout/outage/invalid schema must preserve a useful safe limitation or clarification; no guessed execution. |
| Observability | Structural frame and downstream receipts. | Same receipts plus allowlisted candidate validation/disagreement/timeout metadata, never hidden reasoning or raw provider payloads in trace. |

## Proposed experiment, not implementation approval

Use the existing `SemanticFrameParser` entry point and `SemanticFrame`/`AnswerTarget` as the only semantic output. A candidate may describe objective, operation, known entity/reference candidates, subject, time, qualifiers and requested facets. It must not name tools outside the canonical capability vocabulary or execute any tool. No second memory/parser/orchestrator/store.

Inputs: current utterance, minimum authorized conversational entities and opaque candidate references, necessary prior user facts with provenance and expiry. Do not send unrelated private records or credentials. Public Osa must never receive Office context. Existing disclosure restrictions must also constrain provider inputs.

Validation: closed enums, bounded sizes, known scoped entity IDs, reference ambiguity, speech-act consistency, read/action separation, and explicit missing information. Revalidate actor and target in the existing CapabilityService. Preserve IQ-11B hazard, no-private-read and terminal-cancellation checks before action admission and final presentation. Model scores are not authority or physical verification.

Failure: invalid, unsupported, contradictory, timed-out or ambiguous candidates clarify or retain a demonstrably safe deterministic interpretation. Never make a model suggestion executable without normal proposal/confirmation. A low-confidence answer cannot become an action merely because the model provided a target ID.

## Qualification protocol to approve first

1. Approve provider/model, data-processing boundary and hard spend budget separately. Freeze model/version, input/output limits and per-call deadline before execution. No arbitrary model chosen silently.
2. Start with offline recorded synthetic inputs and schema validation, then shadow-only interpretation. No live customer prompts, physical devices or outbound communications.
3. New independent authors: at least 80 primary multi-turn cases per worker plus 100 paraphrases and 100 operation flips; exclude exposed certification/development utterances. Dual grading plus adjudication of disputes and an agreed sample. Validate fixture authority independently.
4. Compare identical governed evidence and provider-off judgment conditions. Freeze quality gates no lower than IQ-11D and preserve overall independent gates. Zero safety violations, including unsafe proposals, is mandatory. Separately report clarification/coverage, refusals, all worker scores, timeout rate, p50/p95 latency and measured tokens/cost.
5. Run IQ-11C preflight, journal all attempts and exact-ID reconcile all required saves/traces. Integrity gaps block evaluation; no turn replays to repair scores.
6. After review, decide whether a bounded model path is justified. A shadow win is not production deployment approval, strategic judgment qualification or overall intelligence certification.

Recommended boundary: evaluate interpretation, not add more business-judgment calls. Contract-level ownership and provenance corrections remain necessary even if the model experiment succeeds.
