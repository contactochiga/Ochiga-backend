# Oyi Action Truth Contract (Interaction Layer, Slice 1)

## What it is
The canonical conversation response (`POST /oyi/runtime/conversation`) now reports an action's real
outcome inside the **existing** `execution` object. There is no new endpoint and no new action API.

```
execution.status                 "pending_confirmation" | "action_result" | "read_only"
execution.current_turn_execution true only when the device command was executed in this turn
execution.action                 null, or:
  action_id                      the canonical OyiAction id
  status                         canonical OyiActionStatus (ActionStateMachine vocabulary)
  requested_operation            e.g. "device.power.on"
  requested_state                true | false | null
  target.label                   display label only
  truth                          null, or the device ledger's public truth fields:
                                 request_status, dispatch_status, provider_status,
                                 confirmation_status, physical_effect_status,
                                 final_status, truth_state, retryable
```

`execution.action` is built only by `src/oyi-core/actions/actionTruthProjection.ts`. The response adapter
re-whitelists it (`sanitizeConversationAction`), so a capability can't push other fields through. The fields that can never appear are:
- device or provider ids, `external_id`, vendor or provider names;
- raw payloads, command lifecycle, evidence, scope ids;
- `safe_error_message` text.

Persistence already stores `execution.action` as `metadata.action` on the thread and on messages, so restoring a thread recovers the same truth.

## Approval is not verification
| Moment | `execution.action.status` | Meaning |
| --- | --- | --- |
| Oyi proposes a device command | `awaiting_confirmation` | Nothing sent. UI: **"Confirm action?"** |
| User presses Confirm | `approved` (transient) | User approval only |
| Provider accepted, effect unobservable | `unobservable` (or `provider_accepted` in flight) | Accepted, **not verified** |
| Final state observed | `confirmed` | **Verified**. The only verified status. |
| Failure | `failed` / `provider_rejected` / `timed_out` | Stated as failure; nothing is claimed as changed |
| Cancelled / replaced | `cancelled` / `superseded` | Nothing sent |

## Where it is set
| Path | Status |
| --- | --- |
| `DeviceActionCapabilityModules`: device proposal | `awaiting_confirmation` |
| `ConversationOrchestrator.pendingWorkflowStatusResult` | `awaiting_confirmation` |
| `ConversationOrchestrator.durableWorkflowContinuationResult`, confirm | terminal action plus device truth; `executed_this_turn` |
| `ConversationOrchestrator.durableWorkflowContinuationResult`, cancel | `cancelled` |
| Permission-restricted continuation | no action outcome (nothing executed) |

## Executor errors are recorded
`DeviceConversationActionAdapter` now catches errors thrown by `executeDeviceCommandForActor`, which throws on dispatch and provider errors. It classifies them exactly as the device command route does:
- 400 / 403 / 409 / 422 → `failed`, not dispatched;
- anything else → `provider_rejected`.

Previously the error escaped the turn and left the action stranded at `sent`. A retried Confirm then got "no live pending action". Execution ownership is unchanged: the same executor runs, and only its failure is now recorded.

## Cross-surface equivalence (Consumer + Facility)
Choice: a tiny shared mapper plus a shared contract fixture, kept byte-identical in both apps. There is no shared package; the surfaces are separate repositories with separate toolchains.
- **Mapper:** Consumer `src/lib/oyiActionTruth.ts` = Facility `lib/oyiActionTruth.ts`.
- **Fixture:** `docs/contracts/oyi-action-truth.fixture.json` (this repo). It is generated by `scripts/oyi-action-truth-contract-smoke.mjs` from the real `ActionService` → `DeviceConversationActionAdapter` → response adapter chain. It is copied to `oyiActionTruth.fixture.json` beside each mapper.
- **Proof:**
  - `scripts/oyi-action-truth-contract-smoke.mjs` is byte-identical in both apps. It runs each surface's mapper over the fixture: same labels, tones, verified flag and message state, and restored = live.
  - The Backend contract smoke fails if the committed fixture drifts from the runtime.
  - `scripts/oyi-action-truth-live-smoke.mjs` runs both apps' mappers over real live responses and restored thread rows (`OYI_CONSUMER_DIR` / `OYI_FACILITY_DIR`).

To change the contract, regenerate with `node scripts/oyi-action-truth-contract-smoke.mjs --write-fixture`. Then copy the fixture and mapper to both apps.

## Known residuals (not changed in this slice)
- **No live "verified" in a conversation.** A conversational turn only ever receives `provider_accepted` (ack-only) or `awaiting_state_confirmation` from the controller. State confirmation (`state_confirmed`) arrives later in the device ledger, so a conversational device action is recorded as `unobservable` even for state-confirming providers. Presenting it as verified would be false.
- **`timed_out` is never produced.** `DeviceConversationActionAdapter` folds `confirmation_timed_out` / `state_mismatch` into `failed`, so `timed_out` is unreachable on this path. `truth.final_status` still carries the exact reason.
- **Legacy ledger route.** `/ai/confirmations/:id/confirm` (Consumer ledger path) reports dispatch, not verification. Consumer now presents it as "Approved and sent. Oyi has not verified the result."
- **Executor-error ledger row.** The actor execution path has no failure write-back. When it throws, its device command ledger row stays at its last recorded stage (for example `requested`). The canonical OyiAction is now terminal and correct, but the ledger row is the ledger owner's to finalise, and that is unchanged here.
