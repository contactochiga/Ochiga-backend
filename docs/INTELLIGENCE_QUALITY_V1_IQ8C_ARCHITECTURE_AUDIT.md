## Answer to the architectural question (A–G)
It is **G, a combination, with no single dominant cause**: A routing 32%, D answer-target semantics 25% (+6% not applied), C capability-owned templates 15%, composition 8%, B too-weak results 3%, F missing capability 3%, ambiguity 5%. Counterfactual ceilings from 61/126: fixing every routing miss alone gives at most 0.651; every derivation miss alone 0.611; every template override alone 0.563. The gate needs 107/126 (+46), i.e. routing + derivation + template overrides (47 items) would all have to be fixed and then pass. The C–F diagnosis (54% routing) was therefore right about the largest bucket but wrong that routing is "the" problem.
Counts requested: routing-only 21; missing capability 2; capability-result-too-weak 2; derivation failure 16; target-not-applied 4; template/composition 15 (10 + 5); ambiguity 3.

## 2. Response pipeline as it actually runs
utterance → `SemanticFrameParser` (IQ-7 objective, operation, legacy `classifyDomain`/`domainFor`, `conceptBridge` reconcile) → capability resolution (`supports` predicates; surface/authority) → one of five terminal paths:
1. **Read capability** → module `answer()` prose + blocks/metadata → `CapabilityResponseAdapter.shapeReadAnswer` (re-derives AnswerTarget from the raw text, then `targetedRetrieval` / overview / limitation helpers prepend a lead to the module's prose).
2. **Assessment path** (planner → judge → `composeJudgmentText`) → `targetedLead` (re-derives target again inside `judge.ts`) → targeted lead + "Supporting evidence".
3. **Public module** → own acknowledgement/summary templates; `targetedPublicLead` (derives target again) in two of its branches.
4. **Orchestrator direct** answers (constraint ack, action truth, safety report, nothing-pending, menu, out-of-scope), outside the adapter.
5. **Reassessment / action / handoff** modules with their own composers.
Per stage — enters / discarded / re-read / prose / repair: the frame carries objective, domain, concepts; the adapter and judge each call `deriveAnswerTarget(rawText)` again (the target is not carried on the frame); capability modules write final prose and hand the adapter only `answer`, `blocks`, and (for 4 families added in IQ-8) `metadata.answer_rows`; `shapeReadAnswer` re-reads wording again with regexes (arrival, camera, consumption) and re-derives the target; the public module does not receive the target at all except through its own calls. Later layers repair earlier prose: adapter retrieval shaper, adapter limitation helper, judgment targeted lead, public lead.
Duplicated responsibility: target derived 3 times (adapter, judge, public module) + once in the orchestrator; wording interpreted by `classifyDomain`, `domainFor`, the concept bridge, per-module `supports` regexes, and adapter special cases.

## 3. Capability result contracts (from the actual modules)
Structured, usable for list/count/status/yes-no: leads, opportunities, reports, tasks-query, development (block rows + totals); maintenance, visitors, security, wallet transactions (`answer_rows`, added in IQ-8); facility overview (`overview_view`); devices/utilities purchases/spending (table block rows, no typed fields); the assessment path (full `JudgmentResult` + evidence state); the public module (`public_opportunity_objective`: known facts, constraints, changes). **Prose-only:** wallet balance ("Wallet balance: NGN 12,500."), cameras, single-record tasks/meetings/portfolio ("select one first"), capabilities listing. **Gated/weak:** `financial.summary.read` returns "no records" when `estates` is empty although `portfolio` totals exist in the same snapshot; opportunities blocks omit `days_since_activity` that the snapshot holds. Across the 126 items: structured rows/objective/full state were available to the target in 77 (61%); prose-only/template/none in 49.
Contract gaps that block generic targeting: no typed `value` (amount/currency/as_of) for balances, no common `availability`/`limitation` fields (each module words its own unavailability), no typed state fields (open/resolved, stale) on device and utility rows, no declared "history unsupported".

## 5. Response ownership and conflicts
Owners: capability module (prose + blocks), adapter (shaper/limitation), judgment composer, public module, orchestrator (direct/templates), reassessment, action modules. Conflicts: (i) module prose vs adapter lead — both claim the answer, joined by "Supporting detail"; (ii) public module vs `targetedPublicLead` — the ack template decides first for 10 misses; (iii) orchestrator early-direct vs "nothing pending"/menu — order decides; (iv) adapter limitation helper vs module-specific unavailability wording (it overwrites capability reasons with a generic quote); (v) three independent target derivations that can disagree.

## 10. Canonical response projection hypothesis
`utterance → frame → capability → STRUCTURED RESULT → AnswerTarget → projector → response` **fits**: IQ-8 already contains three nascent projectors (`targetedRetrieval`, `targetedJudgment`, `targetedPublic`) and four structured result precedents (`answer_rows`, `overview_view`, block rows, `public_opportunity_objective`). What is wrong is ownership, not direction: the projector sits *after* module prose and repairs it. Migration can be additive: a shared result envelope populated by thin per-family mappers over existing outputs, one `projectResponse(target, envelope)` function, the target derived once and carried on the frame, modules keeping their prose as fallback until a family is migrated. No rewrite is needed. The same migration removes the three-way target derivation and most adapter regexes.
## 11. Minimum structured result (only fields existing capabilities can supply)
`availability` (answered | empty | unavailable | unsupported | denied), `subject` {domain, object_class, label?}, `records[]` {id, label, status/state, detail, time?}, `count`, `total_count`, `truncated`, `value` {amount, currency, as_of} (wallet balance, financial totals), `state_facts` {fresh|stale|unobserved counts}, `limitations[]` {kind: stale | unobservable | missing_capability | scope | permission, label}, `provenance` (source keys), `truth_state`, `held_facts` (public: known facts, missing fields, constraints), `actions` (workflow/proposal pointer). Mapping: leads/opportunities/reports/tasks/development → records+count+total (+days-since-activity as a record field); maintenance/visitors/security/transactions → records (already `answer_rows`); wallet balance → value; financial summary → value set from `portfolio`; overview → records + limitations; devices/utilities → records + state_facts; cameras → limitations; public → held_facts; assessment → its existing `JudgmentResult` (already structured).
## 12. What should stay specialized
Action truth and confirmation workflows, reassessment, complex judgment composition, public hand-off/callback truth, safety/authority refusals, capability discovery, corporate-knowledge answers. The projector covers read-shaped answers (list, count, status, detail, yes/no on records, history/limitation, balance/state); it must not become one template engine.

## 13. Wave 11 evaluator defect
Turn `consumer-wallet:2` ("How much electricity have I used?") selects the declared `utilities.usage.read` before and after, with `response_status: unavailable`, `evidence_count: 0` both times. The harness fails any answer containing "is not available" / "can't confirm" / "does not have an enabled"; IQ-8 limitation wording avoided those substrings. Future certification should classify from **structured fields** — capability status (declared/unsupported vs answered), `response_status`, `evidence_count`, execution metadata — into separate counters: `CAPABILITY_SUCCESS` (answered with evidence) and `HONEST_LIMITATION` (unavailable/unsupported, truthfully worded); an honest limitation must never be promoted to capability success by wording, and neither should be failed by substring.
